# InfoFilm pilot

Research → points/narration → selected TTS engine → Whisper audit → MFA word timing → visual plan → Qwen Image assets → Remotion MP4.

VibeVoice narration now uses one clip per point and the native `/render-batch` API. `vibe_batch_size` defaults to four (maximum five); `vibe_max_attempts` defaults to three. Only failed points are regenerated. MFA first retries alignment on the same recording; if both alignment attempts fail, that point re-enters the bounded chunk-generation loop. Logs distinguish `point_alignment_failed` from `point_audit_failed`. A single CPU worker audits and MFA-aligns each accepted clip while the GPU renders the next batch. Joining preserves the original PCM with a configurable 0.18-second pause; global word IDs and timing use exact sample offsets. The narrator reference, CFG 1.3 and native synthesis settings are unchanged. Whole-script auditing also checks point coverage and rejects missing passages/endings that a good aggregate score could conceal.

Completed runs expose **Repair narration and subtitles** in the web interface. The same operation is available with `create --project PATH --resume-from narration`. It reuses the saved script, source evidence, approved images and word-anchored visual plan, then rebuilds narration, timing, music and video. Original deliveries remain archived. Caption and image timing changes require a new picture render; replacing only the audio would retain incorrect subtitles.

Mood and direction are resolved after evidence, before writing narration. **Auto is the default.** The same saved creative brief guides wording, visual style, explanatory-graphic balance, pacing, colours and optional music. Exposed presets are Professional, Warm/Friendly, Lightly Funny, Curious/Wonder, Serious/Documentary, Reflective/Sad and Inspiring/Hopeful. Intensity defaults to Restrained. All imagery is generated; the subject determines photographic, painterly or editorial treatment. Visual balance can remain Auto or be overridden with Image-led, Balanced or Explanation-led.

Visual generation follows MFA. A narration point can contain several visual beats anchored to its aligned word IDs. Actual audio duration supplies soft shot/asset guidance; a longer version can allocate additional images instead of sharing a fixed-size library with its shorter version. Native graphics explain useful mechanisms/comparisons, and numerical facts can also use crisp banners or captions over contextual imagery. Image-led scenes use fuller imagery and smaller overlays. Each film saves `visual-metrics.json` with shot count, distinct images, image screen-time share, hold lengths and graphic justifications.

Select **Background score → Auto · ACE-Step** to generate an instrumental underscore; Off remains available. The adapter uses the installed standard Turbo checkpoint, eight steps, no LoRA and no internal music LM. It does not inherit the existing song server's rhyme LoRA/settings. A one-shot process owns the shared GPU lease and exits before the next GPU stage. Scores are cached separately and retried up to three times for technical defects or vocal-screen findings. Music screening first uses local Silero speech activity; when no speech-like regions exist, it skips transcription. Detected regions are checked with the installed stable-ts large-v3 runtime, using raw audio by default as the active rhyme webapp/batch path does. Confident words must overlap detected speech and have plausible timing before rejecting a take. Unsupported fragments remain ambiguous. Optional `music_vocal_isolation: true` enables the installed Demucs vocal isolation for inspection only. Screen artifacts retain regions, transcripts and decisions. ASR and speech detection do not establish musical quality or guarantee absence of humming; listening review remains pending.

Music is generated against actual narration duration and mixed separately with speech-driven ducking and fades. The original narration WAV remains the input to Whisper/MFA. The mixed stereo master receives another Whisper audit, bounded lower-music-gain retries and final MP4 waveform QA against that master. Music and image repair stages reuse approved narration. Score and mixed-WAV downloads appear in the web run after mixing; narrator-only downloads remain separate. Technical/listening-review metadata is saved with each selection.

Delivery audio receives a default +4 dB boost after voice/music mixing, with a 0.95 peak limiter and compensated timing. `delivery_gain_db` in `config.json` controls this gain (0 disables the boost). Speech-only videos use the same delivery setting. Raw narration stays unchanged for Whisper/MFA, and chapter assembly applies gain once from the original stems. Changing the setting creates a new delivery master; existing completed videos retain their published audio until resumed/remixed.

Completed runs expose **Update background score**. This starts at the music checkpoint, uses the saved mood direction and narration, and replaces audio in every finished version with FFmpeg video stream copying. It does not invoke Remotion or repeat research, narration, MFA or image generation. Encoded video hashes must match the original; the new MP4 receives full delivery and audio synchronization checks. Earlier MP4s and delivery metadata remain archived. A failed score revision can use **Resume saved run** to reuse generated scores and completed mixes.

```bash
python -m infofilm create --project artifacts/runs/PROJECT \
  --resume-from music --music-engine acestep
```

The reusable wrapper is `scripts/add-bgm.sh PROJECT_FOLDER_OR_MP4 [acestep|none]`. It accepts a completed project folder, an original delivery MP4, or an exported review MP4 while its source project is still available. It updates all completed versions using their original checkpoints; `none` restores narration-only audio.

OmniVoice now defaults to **native speed 0.8**; its speed control is exposed in the web app and `--omni-speed` on the CLI. Speed participates in calibration and audio cache identity. VibeVoice's synthesis parameters are unchanged. Narrator mood is shaped through text and sentence rhythm with the fixed reference; this installed Omni build does not expose validated emotion instructions, so the application does not claim direct emotional voice control.

```bash
python -m infofilm create --subject "How puppies learn" --duration-seconds 60 \
  --mood warm --visual-balance image-led --music-engine acestep \
  --tts-engine omnivoice --omni-speed 0.8 --orientation both
```

Choose **Kane** in the narrator selector, or pass `--narrator kane` on the CLI, with either narration engine. Its original `~/story_generator/kane.wav` is copied to `references/kane.wav`; CPU Whisper confirmed the same Mumbai passage as the default sample, with a perfect normalized transcript match. Named voices carry their own exact transcript automatically. `--reference-audio` selects a custom recording; it cannot be combined with `--narrator`, and a custom Omni reference needs `--reference-transcript`.

The running Vibe chunks API under `~/vibe/api_server` accepts audio-only voice conditioning in both `/render-chunk` and `/render-batch`. Its installed processor does not consume a reference transcript; adding an extra field would silently discard it. Verified transcripts are retained with narrator profiles and passed natively to OmniVoice. Vibe result metadata distinguishes the saved reference transcript from text actually used for conditioning. Model-side transcript conditioning is a separate unimplemented experiment.

The requested runtime is **advisory**. It guides scope and depth; point flow, subject coverage and narration quality determine the final script. Narration is never sped up, padded, or rewritten merely to match runtime. The final WAV determines every timeline's duration.

The web interface is installed as the `remotion-video` systemd service, listening on `0.0.0.0:8051`. Open [remotion.photovault.live](https://remotion.photovault.live) from another machine and sign in as `nitin`. The HTTPS origin is explicitly allowed. Enter a subject, approximate length, orientation, narration engine and optional second length or reference WAV, then watch stage progress. VibeVoice remains the default; OmniVoice is an English narration option. An uploaded reference requires its exact spoken transcript for OmniVoice. Narration and its point-by-point script appear as soon as audio is ready; passed videos, sources and downloads appear when rendering finishes. The accepted monsoon pilot and completed CLI films also appear in the library.

Failed or interrupted web runs show **Resume saved run**. Resuming keeps their project folder, cached drafts, source pages, provider job IDs, audio and images. Web runs use a persistent single-worker queue; active workers can finish across a web service restart. Source and stage histories remain on disk. To manage the installed interface:

```bash
sudo systemctl status remotion-video
sudo systemctl restart remotion-video
sudo journalctl -u remotion-video -f
```

The login password is stored as a PBKDF2 hash. Its per-user salt is derived from a private, random installation key when needed and is never stored as a separate value. Browser sessions are revoked on password change. Change the password interactively with `scripts/change-password.sh`; the password is never a command-line argument. The installation script is `scripts/install-service.sh`; the service unit is [`deploy/remotion-video.service`](deploy/remotion-video.service). Provider credentials used by systemd are in a private, ignored `.service.env` file. Web endpoints and media downloads require the login, and `https://remotion.photovault.live` is the allowed cross-origin caller.

Web workers inherit `NoNewPrivileges=true`. GPU parking therefore uses plain `systemctl --no-ask-password` for the shared VibeVoice system unit, with the root-installed [`deploy/50-remotion-gpu-services.rules`](deploy/50-remotion-gpu-services.rules) authorizing only user `nitin` to start/stop `vibevoice-api-local.service`. Install that permission separately with `bash scripts/install-gpu-permissions.sh`; Polkit reloads rules automatically. Qwen remains a user unit. VibeVoice's unit, API port and Story Generator's existing system-unit integration are preserved.

VibeVoice release also verifies its installed service PID's actual allocation with `nvidia-smi`. If `/unload` reports no model but more than 512 MiB remains, InfoFilm rechecks that the provider is idle, stops/starts only `vibevoice-api-local.service`, and verifies the recovered idle API and allocation before another GPU consumer proceeds. Speech, image, OmniVoice and music handoffs use this check. Active jobs are never recycled. Batch results and downloaded clips are saved before recycling; incomplete downloads defer recycling, and saved terminal batch results remain usable after the provider's in-memory job registry is reset. `gpu` events distinguish `release_incomplete`, `service_recycling`, `service_recycled` and verified `released`.

New VibeVoice chunks, calibration and OmniVoice submissions expand numeric notation into explicit spoken words before synthesis, using the same expansion as MFA. This covers years, decade compounds, decimals, percentages, ranges and ratios. Source scripts, headings and captions keep their original spelling, and saved provider submissions/recordings remain immutable on resume. English audio scoring separately recognizes equivalent quantities such as `a thousand` and `1,000`, while retaining guards for changed quantities, signs and units. A failed Whisper audit is distinct from an MFA alignment failure in the point retry logs.

The CLI remains available for batch runs. For a new subject, `python -m infofilm create --subject "Why volcanoes erupt" --duration-seconds 60 --orientation both` creates a unique project folder. Supply `--project` to resume an existing one. Finished videos are exported to `output/<project-name>`.

This checkout currently borrows Quizmaster's installed Remotion dependencies through `renderer/node_modules`. Do not run an install through that symlink. For an independent installation, remove the symlink, then run `npm ci` in `renderer`. Model/service paths are configurable in `config.json`; credentials come from environment variables and are not written to artifacts.

python -m infofilm create \
  --subject "How the Indian monsoon works" \

```

`--orientation landscape`, `--orientation portrait`, and `--orientation both` select 1920×1080, 1080×1920, or both. Each orientation uses its own composition layout while preserving the same narration and word anchors. Image-led portrait scenes preserve the full generated illustration in a visual panel over a softly blurred background; other layouts reframe the illustration. Inspect actual framing before acceptance.

The command above reuses this pilot's selected images. Omit `--image-manifest` when generating fresh imagery. `--visual-plan-dir` accepts declared editorial revisions while retaining original model candidates.

For a new subject, omit `--sources`, `--script-dir`, `--visual-plan-dir`, `--image-manifest`, and `--use-evidence`. Research runs a local copy of the small kbagent harness, [`infofilm/research_harness.py`](infofilm/research_harness.py), in the existing kbagent Python environment. It keeps full fetched pages and search results, gives each long page a first-pass source digest with traceable passage offsets, then feeds those digests to the research synthesis and evidence planner. A code-enforced conversation bound stops accumulated research messages from exceeding the model context. `research_python` can override the interpreter in configuration. The prompt targets evergreen explanations; current news needs a suitable research brief. `--tts-engine vibevoice|omnivoice` selects the narration engine. `--reference-audio PATH` changes the reference; OmniVoice also requires `--reference-transcript 'exact spoken words'` for a custom reference. `--language en_indian` selects the VibeVoice language key. This release uses English scripts, English Whisper auditing and English MFA alignment; Hindi output requires a separate end-to-end language path. `--duration-seconds 90` is an alias for a single advisory duration. `--until evidence|audio|storyboard|images|video` checkpoints a partial run.

The pilot deliberately supports an editor-supplied `script-{duration}.json` input. Earlier local-LLM drafting trials were over-constrained by hard word budgets and are preserved separately. Those trials do not establish that a two-model loop is ineffective for narrative planning under the revised advisory-runtime policy.

Research extracts PDF text with `pdftotext` before creating source digests and archives the original PDF alongside its extracted text. Unreadable documents, sources without relevant supported claims, and source digests that fail bounded structural repair are recorded as skipped sources; they cannot supply evidence or citations. Research continues using readable sources and still requires at least one usable fetched source. Scanned PDFs without extractable text are skipped until OCR support is added. Install Poppler's `pdftotext` on a new host to enable PDF sources.

Research model calls disable thinking and cap each response at 4,000 tokens. Empty or reasoning-only responses retry up to three times without executing tools or treating internal reasoning as evidence. Response attempts, usage and finish reasons are archived; resumed runs preserve earlier model-call records. Research-worker failures save their underlying error so the interface can display it instead of only a subprocess exit status.

## Review and provenance

Both LLM endpoints are configurable. Experimental text loops retain initial candidates, independent reviews, bounded revisions, blind comparisons, actual token usage and measured latency. Deterministic code validates source IDs and executable shapes. Quantitative measurements come from code; LLM review assesses meaning, flow and visual requirements. Narrative reviewers receive the subject and evidence without numeric runtime targets, because the trial showed that merely calling duration advisory did not stop the smaller model imposing word limits. Broad adoption remains pending evaluation across more subjects.

The monsoon scripts are attributed assistant editorial revisions. Both models review their semantic quality. Source-audit findings and adopted wording corrections remain available under `pilots/monsoon/scripts` and `artifacts/monsoon`.

Qwen Image requests use the user-selected local service. A cooperative host GPU lock and service busy checks serialize narration/images. OmniVoice starts only when missing narration clips need generation and releases the GPU afterward. It saves per-point WAVs, audits each point, and makes up to five attempts (`omni_max_attempts`, including the first take), regenerating only failed points. Saved passing clips are reused on resume. Whisper comparison expands numeric notation such as `22.5%`, `7–10`, and `1.4:1` into spoken words while rejecting changed quantities and preserving raw transcripts and original audit metrics. Selected clips are joined for the existing whole-script Whisper audit and MFA timing. This lock coordinates InfoFilm processes; other applications must cooperate for complete cross-application scheduling. Provider job IDs are checkpointed, and unresolved submissions are not blindly retried.

Whisper passes go directly to alignment, with no LLM call. Failed text/coverage audits receive a cached semantic review (`audio_audit_llm_review`, default true): the reviewer sees the script, raw transcript and every mismatch, and can accept a non-English name's phonetic spelling, word-boundary error or harmless disfluency. Every mismatch must be accounted for; changed numbers and detected missing passages remain guarded. Original failed metrics and the LLM verdict stay in `audit.json` and `audio-semantic-reviews/`; a semantic pass keeps its original numerical score. If review cannot accept the transcript, up to two stronger CPU recognizers can cross-check the same recording (`audio_audit_fallback_models`: small, then large-v3-turbo; an empty list disables them). No script is supplied to ASR. This applies to both speech engines and does not change VibeVoice synthesis. Transcript review does not verify pronunciation by listening.

The [OmniVoice model card](https://huggingface.co/k2-fsa/OmniVoice) lists the pretrained weights as CC-BY-NC. Check that license and the rights to any cloned reference voice before using generated narration beyond permitted non-commercial work.

The final image prompt stage receives exact narration, neighbouring beats, visual intent, measured scene length and intended orientations. It generates prompts for assets actually used, accounts for shared imagery, and proposes context banners. Remotion places those banners legibly over the images. Optional `banner_override` fields retain declared editorial choices. Captions preserve the original spelling and punctuation, and stop at point/sentence boundaries.

Image review logs explicit `accepted`, `rejected`, `retrying`, `prompt_repaired` and `exhausted` decisions, alongside the planned/reused/remaining image counts. A rejection triggers a complete replacement prompt using the reviewer feedback and narrated context, with confusing nouns replaced by unambiguous synonyms (for example, “document stamp” for a legal “seal”). Generation receives the overall subject; repair and review also receive the sourced facts and shared visual brief, preserving dates and geography when the local passage does not repeat them. The planner is instructed to preserve already-correct elements and remove repeatedly faulty optional decorations, while preserving the narrated meaning. Code rejects exclusion clauses and duplicated adapter prefixes before submission; the actual replacement prompt is logged. Prompts describe the desired scene positively; the local image API has no negative-prompt field. The default limit is five image takes (`image_max_attempts`, including the first; configurable from one to five). Original prompts, rejected images and reviews remain preserved; accepted images are verified and reused, and the image manifest checkpoints each acceptance.

Image framing is shared between final prompt planning, generation, repair and review through `infofilm/composition.py`. Standard landscape scenes reserve the left 43% for text and group essential content on the right; standard portrait scenes protect the renderer's right-biased crop. Minimal-copy scenes allow natural full-frame imagery and centred subjects, with text below. Shared images satisfy all their actual scene uses. Banner space is required only where the banner overlaps the source image; minimal portrait delivery contains the image beneath the banner. The generation adapter puts concrete positive framing instructions before scene detail. Reviews must identify actual content lost beneath an overlay or crop, and cannot reject an image merely for being right instead of right-of-centre, or demand empty left space in minimal scenes. Historical/geographical/scientific mismatches remain rejection reasons and cannot be excused in limitations as an illustrative style choice.

The saved Mughal placement audit found nine layout-related rejections among 26 rejected takes, affecting four assets, across 65 reviewed candidates. Initial prompts already specified right-side placement. Two isolated saved-image probes under the revised policy accepted a usable measuring-rod image in a minimal scene and still rejected a modern-border map for geographical/historical errors. An earlier probe that excused the map mismatch is preserved in the request traces; the tightened review instruction corrected that result. These probes do not establish a general reduction in image retries. Artifacts are in `artifacts/image-placement-audit/`; production images/reviews were not modified, and the running workers were not restarted for this change.

`report.json` records first-pass acceptance, acceptance within two takes, final acceptance, failed/repaired images, total generation requests, warm request latency, generation time per accepted image including failed takes, and planner/reviewer tokens and latency. Timings include service overhead and separately identify the first request's model loading. Historical Qwen accepted-take latency is a reference, not a fresh controlled baseline. A separate final text audit checks selected images for generated titles/labels even when correctly spelled: readable raster titles were occasionally missed by the main reviewer. This audit leaves all original loop decisions intact and reports those false positives separately. `--skip-text-audit` omits this additional evaluation. A failed/unresolved final audit also gives exit status 1.

`output/<project>/turbo-benchmark/<test-hash>/index.html` compares production Qwen images with turbo results and lets you inspect every rejected take, replacement prompt and review; it updates after each review. Production image assets, manifests, prompts and video delivery are never replaced by this test; their checksums are verified afterward. Automated acceptance requires a human review before choosing a production engine.

MFA is reused through the existing generic alignment function, without a story database ID. Its input expands numeric notation and decade compounds such as `mid-1970s` into spoken words; captions keep the original script spelling and use the combined MFA word spans. Decade expansion is limited to MFA and preserves the existing Whisper scoring policy and native speech cache. Alignment recovery makes at most two adapter attempts, with visible `attempt_failed` and `retrying` events: preserved pre-fix numeric failures retry with expanded input, and fresh alignment failures retry with a wider search. The adapter also has three bounded decoder beam attempts. Failed raw results and attempt history remain available; alignment repair preserves the approved audio. Whisper audits check transcript coverage; they are not a claim of full human listening. Remotion renders from an executed source/media snapshot. Filmora's direct-WAV mux and decoded-waveform QA verify delivery timing. Browser snapshots measure text fit and caption clearance in both layouts; sampled inspection is reported separately from human acceptance.

SQLite records pipeline events and web queue state. Web jobs use detached worker processes, preserving ongoing work across a web service restart; immutable request/result files and provider job IDs support resumption. A distributed worker or other GUI integration can call the same pipeline operations. The web service serves one queued film at a time.

Image provider routing is configured in [`image-providers.json`](image-providers.json), loaded by `image_provider_settings` in `config.json`. Provider IDs are separate from adapter IDs and model IDs: `qwen_local` uses `qwen_async` on port 8075; `flux_dev_local` uses `imagestudio_sdapi`, engine `flux2`, on port 8000. The installed premium model is **Flux.2 Dev**. Endpoints, inference settings, ordered tiers and retry budgets can change in this JSON without changing subject plans. Credentials belong in environment variables; URLs with embedded credentials are rejected. The isolated [image ladder experiment](pilots/image-ladder/README.md) compares the current full-resolution repair loop with low-resolution/low-step previews, normal-step previews, final generation/review and Flux recovery on 20 saved difficult cases. Its two scripts prepare only unless passed `--execute`; they use separate outputs, frozen matched inputs and a separate final-image audit. Production generation remains unchanged while the strategy is evaluated.

The default policy, `standard_then_premium`, allows five Qwen takes and five Flux takes, with an overall limit of ten generated candidates per asset. New visual reviews must return validated `reason_keys`: `unwanted_text`, `semantic_mismatch`, `factual_mismatch`, `composition_obstruction`, `visual_artifact`, `prompt_ambiguity`, `backend_corruption` or `uncertain`. Acceptance requires an empty list; rejection requires concrete visible evidence and at least one known key. Invalid review JSON gets one format repair against the same image, then stops rather than spending another image generation.

Code owns routing: `unwanted_text` triggers escalation after at least two attempts containing a meaningful prompt change, regardless of the reviewer's cause, confidence or recommended action. Technical corruption takes precedence and stops for backend diagnosis. Other failures require an evidenced provider diagnosis with at least 0.8 confidence and the same repair gate; a contradictory `repair_prompt` recommendation no longer overrides that provider diagnosis. Legacy cached reviews retain their original diagnosis without guessing structured keys from prose. Otherwise prompt repairs continue within the current budget. Exhausting a prompt-repair budget does not automatically spend premium generations. Unresolved submissions stop for backend diagnosis. The last tier also has a bounded budget; an unresolved asset stops publication.

Only failed assets enter the premium tier. Its counter starts at zero; total attempts and every earlier candidate/review remain recorded. The premium prompt planner receives earlier defects and repairs, source facts and the shared style. Assets are grouped by tier to avoid pipeline unloads between individual images; ImageStudio still applies its own model lifecycle settings. Flux generation holds the shared GPU lease, parks only the known idle Qwen/Vibe services to release their CUDA contexts, and restores them afterward. It never interrupts active work. Existing accepted Qwen checkpoints keep their original cache identities and are verified/reused.

The Qwen provider runs as a user service, while the web worker is launched by a system service. The GPU-switch adapter supplies the user's runtime directory and session-bus address for all user-systemd checks, stops and restores when those variables are absent. An unreachable service manager is reported separately from an inactive provider; Flux model loading starts only after the idle providers have been parked and the GPU verified clear. A Qwen service check during Flux escalation is therefore part of GPU cleanup, not a request to render the premium image with Qwen.

Each run saves `image-provider-policy.json`, `image-escalation-report.json`, and the final provider/tier/attempt attribution in `image_manifest.json`. Web submissions embed the complete provider registry in their configuration snapshot: changing settings affects new submissions, while resumptions retain their original policy and budgets. To run without premium escalation, set `"image_provider_policy": "standard_only"` in `config.json`, or pass `--image-provider-policy standard_only` to `python -m infofilm create ...`. It shares narrator and visual identity while Auto mood and musical direction can develop across chapters. Detailed imagery is planned after each chapter's measured narration.

Chapter progress, logs, approved plan, narration and completed chapter previews remain accessible from the parent run. A failed chapter is recorded while subsequent chapters continue. **Resume** reuses checked completed chapters and retries incomplete ones. A failed production also releases the queue for the next production. Final assembly requires all chapters and a continuity review of adjacent actual narrations; minor editorial findings are advisory. Major factual or continuity failures retain the chapters for targeted review.

Continuity decisions log the pair, score and actual issues separately from the successful LLM API call. A successful call does not mean the review accepted the chapters. For a reviewed editorial deletion from a completed chapter, `scripts/remove-completed-film-points.py --project CHAPTER_FOLDER --drop-points P11 P12 P13 --reason "Reviewed duplication repair"` removes complete points, proves all retained PCM samples are unchanged, preserves MFA word IDs, retimes captions and image beats, reuses existing images/music, and rebuilds the chapter. Originals are archived; publication follows layout and waveform QA. This is an explicit editing tool, not an automatic removal policy. Review the proposed revised script against both neighbours before applying a cut.

Long-film parent logs relay each chapter worker's stdout/stderr with chapter ID, position and elapsed time, including image counts, acceptance, repair prompts and provider escalations. Child output remains in its durable `attempts/.../worker.log`; the parent tails it every two seconds and persists its byte cursor for reattachment. Stage summaries appear only when the stage changes, with a heartbeat after a minute without child output. Final diagnostics are drained on success or failure. Keeping child output in a file preserves logging across parent interruption, without making the worker depend on a live pipe. A restarted parent can reattach to a still-running chapter instead of rerendering its work.

The join reuses an approved image from each incoming chapter for a section card, inserts a brief narration pause, crossfades separate instrumental scores and ducks music under unchanged speech. FFmpeg joins encoded chapter pictures without another Remotion render; frame counts, caption offsets, delivery audio and video decoding are checked. Both landscape and portrait are supported. Parent artifacts live in `chapter-plan.json`, `longform-status.json`, `chapters/`, and `videos/`. Long parents currently resume through their saved run; the short-film music/narration revision buttons are disabled for them.

  --orientation both --music-engine acestep --project artifacts/mughal-long

On uses both configured models to select/review a known subject category, then carries its inherited questions and prompt shape through parent research, source-backed orientation and chapter planning. The brief is JSON with `sources[{id,url,title,excerpts:[text]}]`, `anchors[{id,claim,source_ids,event_years?:[integer]}]`, `required_anchor_ids`, optional `coverage_requirements`, and `cautions`. Source excerpts must support the anchors. Keep this brief small; code bounds its bytes and each model request. Focused `research_queries` and `research_gaps` in the resulting plan identify work for later chapter research. The pilot archives complete fetched pages separately for traceability.

Output `chapter-plan.json` uses `infofilm.chapter-plan.v0`: one central question/narrative arc; a coverage ledger assigning each topic to exactly one chapter; chosen structure and rationale; chapter scope, objective, source IDs, advisory length, opening/closing roles, entry context, handoff, exclusions, subject-appropriate mood, instrumental score direction and visual/card guidance; and assembly intent. Structure is chosen independently of optional user year bounds. Chronological plans order dated chapters forwards and keep explicitly dated anchors inside their owning chapter’s scope. Thematic/hybrid chapters may overlap in time. Either date endpoint may be null when unknown or irrelevant, including for historical themes; meaningful date gaps and unreached scope endpoints are semantic-review warnings rather than exact-partition code failures. Only the first chapter has a film introduction and only the last has a film conclusion. Section-card instructions refer to an approved image from the incoming chapter; images and their IDs do not exist at this planning stage. Image counts remain a later MFA-based decision, and clean narration/music stems stay separate for eventual score transitions.

Planning uses a bounded draft → independent review → repair loop. Code validates references, coverage ownership, declared structure, optional date endpoint shapes and executable shape. Redundant source lists are enriched from owned anchors, and known final-conclusion enum aliases are canonicalized with an audit record; raw drafts remain preserved. The semantic reviewer receives no schema-error dump to speculate about; an LLM rubric assesses grounding, coverage, chapter coherence, flow, mood and readiness. Semantic reviewers receive no exact runtime target. Allocations outside the present child pipeline's usual 60–180-second range are reported as future integration warnings, not rejected for length. `candidate-*.json`, `review-*.json`, token/latency records, `evaluation.json`, and `plan-review.md` retain the initial baseline and selected plan. When repairs change the plan, a label-blinded comparison records whether the reviewer prefers the revision. These are model assessments, not proof of human acceptance or finished narration quality. A plan that exhausts review is saved for inspection but is not published as approved `chapter-plan.json`.

For a focused revision, supply `--revise-plan path/to/chapter-plan.json --feedback path/to/feedback.json` in a **new output directory**, together with the original subject/brief/scope flags. Feedback is a JSON object describing concrete defects and desired corrections; the prior plan and feedback are archived, and the blind comparison uses that prior plan as its baseline. Code rejects copied mood/music placeholders and identical music directions across all chapters. A recurring shared motif remains desirable, with chapter-specific instrumentation, energy and transitions. Chronological ranges can share a boundary year or use consecutive inclusive years. The reviewer assesses coverage across longer date gaps. Model roles come from settings or `longform_planner_role`, rather than being inferred from dates in a title.

Feedback can include `must_change_fields`, for example `["chapters.C04.entry_context", "film.shared_visual_style"]`. Code rejects unchanged or missing flagged fields; this prevents silent omission of a requested repair, while the independent reviewer still checks whether the new meaning resolves the evidence-backed finding. A wording change alone is not proof of factual correction. All scene imagery is planned as generated artwork or reconstructions with native explanatory overlays; archival/stock footage is outside this prototype's production contract.

The first live efficacy trials and their limitations are summarized in `artifacts/external-planner/pilot-summary.md`. Integration has been checked with failure/resume and queue regression tests, a prepared Mughal plan through the production CLI, and an actual FFmpeg join with chapter music and silent narration gaps. A complete new 10–15-minute media production still needs end-to-end listening and visual review; model scores and synthetic join checks do not establish that acceptance.

## Message-preserving image recovery

New web jobs use `image_recovery_mode: "message_v1"` in `config.json`. Final image planning supplies `visual_message` (the informative meaning), concrete `setting`, and `visual_style` separately from scene staging. These fields travel with scenes, submissions, reviews, repairs and selected assets. Generator wrappers exclude film/chapter titles and composited banner instructions.

The critic receives only the current submitted prompt, message and actual image. A pass ends the loop. A failed image leads to a targeted correction or a simpler subject-specific scene preserving meaning and source facts. Generation stays at full resolution on the configured single provider, with three candidates by default. Positive wording is preferred; a bounded cleanup may improve it, but ordinary negative wording does not block a valid replacement. Unknown submission outcomes cannot be silently resubmitted. Progress logs show image position, completed/accepted/blocked counts, and remaining assets. Artistic exhaustion continues other images. With terminal recovery enabled, exhausted images enter the scored premium rescue described below; otherwise unresolved assets block video publication.

`image_recovery_provider` selects an adapter from `image-providers.json`; `image_recovery_max_attempts` sets the bounded candidate budget. Old config snapshots without this mode keep their previous provider/escalation behavior.

**Image review** is a separate switch, enabled by default. In the web app choose Off to generate each initial planned image once, without image assessment, prompt repair or premium escalation. CLI: `python -m infofilm create --subject "Example subject" --no-image-review` (use `--image-review` to enable it). Script and image-prompt planning reviews still follow the independent planning-review setting. File decoding, blank-image, dimensions and delivery checks remain active. Saved assets explicitly record `selection_status: "unreviewed"`, review skipped and a null pass result. Reviewed and direct-generation checkpoints are separate. Failed web runs can change Image review when resuming; completed chapters and upstream narration/plans remain saved.

If the Qwen API returns 404 for a saved job ID after a service restart, the pipeline restores the model if needed and resubmits the exact saved prompt, seed and generation settings. Logs show `job_missing` and `job_resubmitted`, including both IDs. `image_missing_job_retries` defaults to two replacements per submission checkpoint, retained across resumes (0 disables recovery). Other HTTP errors, timeouts and submissions without a confirmed job ID do not authorize duplicate requests. A lost job replacement is transport recovery, independent of the artistic review budget, and also works with Image review off.

New runs also enable **sourced person references** through `person_references.enabled` in `config.json`. Initial image-prompt planning includes `people_in_frame` with canonical names, scene appearance context and `reference_kind` (`photograph` or `historical_portrait`). Only named public historical figures visibly depicted in that scene are listed; mentions in narration, generic crowds and objects do not request a portrait. Figures before photography use documented portraits/sculpture depictions, never invented camera photographs or actors.

A specialized research worker uses Wikimedia file metadata and the research stack's Tavily search/extraction service to discover and read source pages. Both LLMs assess caption-based attribution and suitable appearance; code downloads only a supplied image URL, validates it, and archives source URL, actual file hashes, depiction type, source date/credit/license when provided, and qualifications. Search-image hits without a fetched page association are insufficient. A documented adult reference from another adult period can guide facial features while the scene determines age and clothing; the difference is recorded. Unavailable or uncertain references are explicit in `person-references/manifest.json`, logs and delivery `person_reference_gaps`, rather than marked as sourced likenesses. Portrait authenticity and approximate dates retain the documented source qualifications. Archive fallback respects Wikimedia robots-policy 403 responses. A reserved broader-search page allows references outside the preferred institutional domain list while preserving the fetched-page budget.

Code builds a labeled contact card containing only each scene's cast. Qwen receives it through multipart `references`; Flux.2 premium recovery receives the same card through `referenceImages`. Image reviews see the candidate and card separately and assess observable appearance in the requested treatment. Repairs retain the planned cast and card; missing-job recovery reuploads identical checked bytes. No-review mode still uses the references but skips generated-image assessment. Labels/layout are reference-only conditioning, never placed in the finished video. Cards and portrait downloads are reusable across chapters in the same parent film, with separate keys for scene appearance context. Old frozen configurations without this setting retain their original plans and cache identities.

`person_references` bounds source work (`max_people`, default 12 per chapter; `max_candidates`, default 5; `max_source_pages`, default 3) and card panel dimensions. Up to six named figures can share a scene. The worker uses the application's Python/Pillow environment and the existing `TAVILY_API_KEY`; `person_reference_python` can override its interpreter. It runs before image-provider GPU acquisition and never needs a generated portrait.

`--resume-from images` validates saved narration/audit/MFA and goes directly to visual planning, images, score and delivery. For an existing web job, `Queue.revise_images(job_id, chapters=["C02", "C03"])` first archives selected chapters' visual plans, images and downstream videos in `image-revisions/`, preserves upstream checkpoints and unselected completed chapters, then requeues the same parent job. A long-film chapter failure still advances to the next chapter; a normal resume reuses completed results.

Image prompt planning in message recovery mode runs in batches of at most eight assets, with all usages of a shared asset kept together. Each batch gets relevant evidence, chapter scope, narration/neighbouring beats and the film-wide style. Accepted batches are checkpointed independently; combined output must cover every asset and banner exactly. The LLM client records output-limit failures explicitly and retries malformed draft/review JSON within fixed budgets rather than publishing a partial plan.

Read-only ongoing failure tracking: `python scripts/track-run-failures.py --project PROJECT --watch --queue-db artifacts/interface/queue.sqlite3`. Reports under `PROJECT/failure-tracking/` include accepted counts, reviewed candidates, terminal failures, latest review evidence and repair modes. It exits after the queue job stops and never changes generation checkpoints or GPU state.

Vibe long-pause cleanup uses the story stack's gated-deploy policy: scan 50 ms PCM windows at -40 dBFS, compress pauses of at least four seconds to 1.25 seconds, and retain every other PCM sample unchanged. Point clips are cleaned before Whisper/MFA; joined offsets are calculated from the cleaned clips. A second scan catches pauses spanning a clip join and remaps the saved MFA words outside those cuts. Raw provider files remain intact and cached clips can be cleaned without another GPU render. `vibe_silence_cleanup`, `silence_db`, `silence_max_pause_seconds` and `silence_keep_pause_seconds` in `config.json` configure this gate. Omni synthesis and Vibe speaking speed are unchanged.

For a completed film: `python scripts/repair-completed-film-pauses.py --project PROJECT`. The tool archives the original delivery/selections, rejects cuts overlapping any MFA word, remaps word and scene anchors, applies the same edits to the existing scored master, and recompiles with the accepted images. It verifies retained PCM byte for byte and publishes only after layout and video/audio QA. A fresh ASR disagreement is preserved explicitly; an already approved recording can retain content approval through verified silence-only edits. It never applies that inherited approval to newly generated narration.

Terminal image recovery: `image_terminal_recovery` in `config.json` defaults to enabled, provider `flux_dev_local`, and one premium candidate. After exhausted scene attempts or a blocked repair, `image_terminal.py` generates that premium candidate, then scores every saved candidate against the same latest prompt, visual message and acceptance rules. Blind reviewer marks are message (50), prompt adherence (30) and usability (20); code sums them. The highest score wins, with premium winning ties. This is best-available selection, not a fabricated review pass. Every such scene visibly carries **AI generated, needs expert review** at the top left, including when the scoring reviewer passes it. Actual failures and marks remain archived. Technical corruption, changed files and unreconciled submissions still cannot be silently selected. Completed selections reuse their score records and avoid another GPU load. Old snapshots keep terminal recovery disabled unless explicitly updated.
